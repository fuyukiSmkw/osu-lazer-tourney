# AGENTS.md — osu-lazer-tourney (lazer!tourney plugin)

> Architecture overview for agents. Read this before changing code. When touching multiplayer/spectating, always compare against upstream `../osu` (the osu!lazer codebase + `osu.Game.Tournament`). Framework code at `../osu-framework` (only for code reading; build reference is from NuGet, not this dir).
>
> Comments/strings in code must be written in English (except for existing/reusable localisations).

## 0. Goal in one sentence

Reuse the outer UI/art assets and bracket data model of upstream `osu.Game.Tournament`, but do three things upstream cannot:

1. Replace the **chroma (green-screen) area** at the centre of the Gameplay screen with **lazer multiplayer spectating** (one client watches every player in the room, progress kept in sync);
2. Add a **Room tab**: create/join lazer multiplayer rooms inside the plugin (this used to be the job of the external osu!tourney process);
3. Fold **referee operations into the plugin**: clicking a map in Mappool changes the room's current map, the ControlPanel can start matches, and `/commands` in the chat box call the Referee hub API.

Status: all of the above is essentially implemented. This repo is a **lazer plugin distributed as a ruleset** (drop the built dll into the `rulesets/` directory).

- Target framework `net10.0`; references `../../osu/osu.Game` and `../../osu/osu.Game.Tournament` only (see `osu.Game.Rulesets.LazerTourney.csproj`). It must **never** reference the Osu/Taiko/Mania ruleset assemblies: `RulesetStore` scans our dll with `GetTypes()`, which resolves signature-level references eagerly, so any field/signature/attribute naming those assemblies breaks plugin loading when they resolve late (dev builds, custom storage locations). ## 2. Boot chain (how the plugin parasitises lazer)

Upstream `osu.Game.Tournament` is a standalone process (`TournamentGame : Game`, builds its own Host/Storage/API and polls the playing client via `FileBasedIPC`/`StableIPCClient` under `IPC/`).

This plugin is a **single-process Screen** with 4 hops:

1. `LazerTourneyRuleset.CreateIcon()` returns `IconWithListenerLoader`. `CreateIcon` is the only reliably-invoked entry point called frequently by `OsuGame`; its `[BackgroundDependencyLoader(permitNulls: true)] load(OsuGame, Storage, IModelImporter<BeatmapSetInfo>, IAPIProvider)` grabs the host game's DI objects and calls `ListenerLoader.INSTANCE.BeginInject(...)`. Failure only logs — **it must never crash the host game**.
2. `ListenerLoader/ListenerLoader.cs` (singleton): re-entrancy guard (keyed on `game.Toolbar.GetHashCode()`), adds a `DllResourceStore` for embedded resources to `game.Resources`, then `scheduler.AddDelayed(() => game.AddRange(injectors()), 1)` attaches the handlers to the `OsuGame` scene tree so they get full DI. Currently injects `LazerTourneyRulesetIconListener + ScreenHandlerManager + SentryLoggerDisabler` (`NewVersionNotificationListener` exists but is not registered).
3. `LazerTourneyRulesetIconListener` subscribes to `IBindable<RulesetInfo>`: when the user clicks the `lazer!tourney` icon in the mode selector, it does **not actually switch rulesets** (immediately bounces back to the old value; on cold start it first parks on an available ruleset to avoid null) and instead calls `game.ScreenStack.Push(new TournamentGame())`.
4. `Tournament/TournamentGame.cs : TournamentGameBase : OsuScreen` is the plugin's root screen; `TournamentSceneManager` (a `[Cached]` `CompositeDrawable`, not a ScreenStack) pre-creates all 16 sub-screens, and `SetScreen(Type)` only does Hide/Show + depth changes, with a persistent background video `TourneyVideo("main")`.

Side effects (`TournamentGame.load()`): forces windowed mode, shows the OS cursor but hides the lazer cursor, narrows `NotificationOverlayToastTray` so it doesn't cover the stream area, hides the toolbar via `OverlayActivationMode = UserTriggered`. On exit/`Dispose`/Alt+F4 the visual/audio settings **must be restored** (see `VisualAudioSettingsController`).

`HandlerExtension` (reflection over private fields/methods/types) and `DependencyContainerExtension` (reflection over the `DependencyContainer.cache`) under `ListenerLoader/Utils/` are fallback hack tools; the current main path only relies on the former idea, the latter is kept in reserve — **before adding a new hack, check whether a legitimate `[Resolved]` will do**.

## 3. Global dependencies from `TournamentGameBase` (resolvable via `[Resolved]` in sub-screens)

- `LadderInfo` (deserialised from bracket.json; global singleton: Teams/Matches/Rounds/Progressions/CurrentMatch/Ruleset). `readBracket()` reads from disk on a background thread + backfills players and beatmaps via `GetUserRequest`/`beatmapCache.GetBeatmapAsync`, then `Schedule`s back to the main thread to `Cache(ladder)`. The reference-rebuilding logic (Match↔Team by Acronym, Progressions by ID, Round.Matches by ID list) is handwritten — any model-field change must update both it and `GetSerialisedLadder()`; don't remove the empty-mod-array normalisation on `RoundBeatmap` (`SafeRequiredMods`/`SafeAllowedMods`). Custom multipliers add `TournamentRound.DefaultModMultiplierRule` (`Bindable<string>`) + `RoundBeatmap.ModMultiplierRule` (plain string, empty = inherit round default, full override); plain-string fields so old brackets read empty = x1 with no migration.
- Custom mod-multiplier rule language (`Tournament/Models/ModMultiplier/`): one rule = one expression over a single score's mods, evaluating to a ≥0 number (`EZ ? 2` = x2 with EZ else x1, ternary else defaults to 1; `has/all/only` combos with `only` = exact set; `MOD.setting` live values + `??` fallback; `count/min/max/clamp/abs/floor/ceil/round`; `//`/`#` comments; full spec in the `ModMultRule` class doc + `ModMultParser` grammar comment). Settings funnel 5 bindable flavours into `ModMultValue`; note `Mod` does NOT implement `IConfiguredMod` (only `APIMod`) — read via public `GetSettingsSourceProperties()` + `GetUnderlyingSettingValue()`, never the internal `SettingsMap`; acronyms case-insensitive, setting names lowercased with underscores stripped, enums as case-insensitive text. Invalid rules → editor red hint, runtime ×1 + `Debug` logs; non-finite/negative results → ×1. Headless tests: `Tests/ModMultiplier/ModMultRuleTest.cs` (new language features must add cases here).
- Mod-multiplier editing surfaces: `Screens/Editors/Components/ModMultiplierRuleEditor` (custom label row + `SettingsTextBox` + hint; syntax always checked, names `Validate`d against the ladder ruleset) used in `RoundEditorScreen` for the round default and inside `RoundBeatmapModEditor` for per-map overrides (syncs a local `Bindable<string>` into the plain model field, same pattern as the `mods` bindable). Its (?) `RuleHelpIcon` (mirroring lazer settings hint icons à la `FormFieldCaption` + `ExternalLinkButton`) jumps to the About-screen guide via `SetScreen(typeof(AboutScreen))`. That guide ("Mod multiplier rules", right column of the 2-column `AboutScreen` grid) plus `GuideTextFormatter` (`` `code` `` = grey Inter, `**bold**`, nestable; `Parse()` unit-tested in `Tests/About/GuideTextFormatterTest.cs`) and the rule playground (private `UserModSelectOverlay` + `ModDisplay` + 4-line result: official, custom, total, and total × 1,000,000) document and demo the language — keep the About copy in sync with it.
- `TournamentOnlineState` (see §4; only starts subscribing to room events after `AddInternal`).
- `TournamentStorage` + `TournamentVideoResourceStore` (`[Cached]`), `RefereeAuthController`, `OngoingOperationTracker`, `VisualAudioSettingsController`, pass-through `BeatmapLookupCache`.
- Extra `[Cached]` services on `TournamentSceneManager`: `TournamentMatchChatDisplay` (full width on MapPool / half width on Gameplay / hidden elsewhere), `TournamentMusicController`, `SpectateSession` (**deliberately hoisted to scene level and kept resident** so clocks don't freeze when a sub-screen hides, see §5), `ChatTimerService`, countdown service/sounds, and `TourneyDataWebSocketServer` (tosu-compatible ws v1 data feed, see §10).
- `SaveChangesOverlay` / `[Cached] IDialogOverlay` are only created after bracket load succeeds and manually `CacheDependency`-ed — don't pop dialogs before that.

## 4. IPC removal → `TournamentOnlineState` (Online/TournamentOnlineState.cs)

`grep IPC` in this repo only hits comments: stable IPC is gone entirely. Its replacement is `TournamentOnlineState : Component`, which projects `MultiplayerClient.Room` into bindables: `RoomJoined / CurrentPlaylistItem / RoomState / Settings / RoomName / LocalUserState / IsHost / IsReferee`, plus pass-through `Room`/`ApiRoom`/`Client` and `GetTeamId()`.

- `SetPendingRoom(room)`: call **before** `CreateRoom`/`JoinRoom` to stash the API `Room` snapshot you intend to use; `onRoomUpdated` prefers it, otherwise rebuilds via `new Room(MultiplayerRoom)` (mirrors `MultiplayerClient.setupJoinedRoom`) and projects `ParticipantCount`/`RecentParticipants` back every update — otherwise `MultiplayerRoomPanel` keeps showing the join-time snapshot.
- `EnsureSpectateAsync()`: forces the local user from `Idle`/`Ready` into `Spectating`. Call once after create/join, and re-assert on `Idle`/`Ready` inside `onUserStateChanged`/`onRoomUpdated` (the server kicks users back to Idle after playlist changes). **The broadcast client never participates** — this is an invariant.
- `onMatchEvent` only handles `RollEvent` → writes `InfoMessage "{user} rolled N points out of M."` into the shared room channel (mirrors `MultiplayerMatchSubScreen`; without it `/roll` looks like a no-op).
- `LastRoomID`/`LastRoomPassword` are in-memory only, for quick rejoin; never persist them.
- `TourneyState` (`Screens/TourneyState.cs`) is redefined as `Idle/WaitingForLoad/Playing/Ranking` (upstream's stable-polling enum is `Initialising/Idle/WaitingForClients/Playing/Ranking`), mapped from `RoomState`: `WaitingForLoad→WaitingForLoad, Playing→Playing, everything else→Idle`.

## 5. Gameplay: multiplayer spectating (Screens/Gameplay/ — the core of the core)

### 5.1 `GameplayScreen.cs`: layout

- Base class `BeatmapInfoScreen`, top `MatchHeader`, bottom `TournamentMatchScoreDisplay`, `SongBar`/chat linkage, `warmup` (total score 0 means warmup, hides header stars), `AutoProgressScreens` (Idle + previous Ranking + not warmup → TeamWin/MapPool after 4s; contract Ranking after 10s) are all carried over from upstream.
- Upstream's central `chroma: Container` (two green `ChromaArea`s sized by `LadderInfo.ChromaKeyWidth`) is replaced by `playOuter: Container[Y=110, Height=512, Width=ChromaKeyWidth]`, split into `redSide`/`blueSide` at 0.5 width each.
- `PlayersPerTeam` (1–4) no longer draws green blocks but calls `rebuildLayout(n) + spectateSession.Assign()`: 1 = single cell filling the side; 2 = `GridContainer 2x1`; 3 = pyramid (centred half-width cell on the top row + 1x2 on the bottom row; **`GridSizeMode.Relative` is forbidden or content gets squeezed off-screen**); 4+ = 2x2. Old layout crossfades via FadeOut+Expire. While `IsFrozen` (room `WaitingForLoad`/`Playing`), **layout and assignment are frozen**; the `Reset spectate` button forces `rebuildLayout` first, then `ResetSpectate()`.
- Scorebar visibility: upstream `expand()` fades in unconditionally; here only when `State==Playing && (room is TeamVersus || HasTeamScores)`. `awardMatchPoint()` reads the live totals from `scoreDisplay` on entering Ranking and increments the winner's `Match.Team1Score/2Score++`, **skipping ties / no-scores / already-decided matches** (upstream judges by IPC Score1>Score2, counting ties as Team2).
- `Show()`/`Hide()` must be paired with `spectateSession.SetGameplayVisible(bool)`: hidden subtrees are not driven by the framework container's Update, and without the notification the session misdiagnoses frozen clocks.

### 5.2 `SpectateSession.cs` (1331 lines, resident under `TournamentSceneManager`, `Size=0, AlwaysPresent`, draws nothing)

Replicates the watching/scoring/sync logic of `SpectatorScreen + MultiSpectatorScreen`, but drives the `SpectateCell`s owned by `GameplayScreen`. Key flows:

- `Assign(force=false)`: bail when cells are missing/not loaded; no room → `fullTeardown()`; `IsFrozen && !force` → return; slow-spectate guard (when a cell is still showing an old item, keep the old match until reset/next `LoadRequested`, calling `masterClock.StopUsingBeatmapClock()` first so stragglers can't seek into a disposed track); `setupClocks()` only when the item changed; `assignSide(red/blue)` rebuilds `cellsByUser`; `syncWatches + recreateScoreProvider`; catch up on already-Playing users with no play yet; `updateScoreBindings + updateMusicSuspend`.
- `assignSide(room, cells, sideIndex, reservedIds)`: uses slot mapping when slots exist; otherwise filters `Role!=Referee && State!=Spectating && BeatmapAvailability==LocallyAvailable`, splits by `TeamID==sideIndex` for TeamVersus (**lazer convention: team0 = red**), or fills the first 2n users red and the rest blue for non-team rooms, then `Take(cells.Count)` and `cell.Assign(username, red/blue/white, userId)`. Cells still showing gameplay (results/last frames) are pinned to `SpectateCell.AssignedUserId`: never relabelled, and their owners are excluded from fresh picks (cleared by `ClearPlay()` on teardown/reset/new match).
- `ResetSpectate()` = `ExitSpectatingToRoom + teardownVisuals + stopAllWatches + local Idle/Ready→Spectating + Assign(force:true)`, discarding last frames/results — equivalent to a fresh `MultiSpectatorScreen`.
- Room events: `onRoomUpdated` (null→teardown; joining a loading/playing room midway → `Assign(force:true)`; otherwise `Assign + checkForAutomaticDownload` — mirrors `MultiplayerSpectateButton`, auto-downloading per-beatmap-deduplicated charts when `automaticallyDownload` is on and the local user is Spectating, via `lastDownloadCheckedBeatmapId`); `onLoadRequested` (new match clears old results/last frames, then `Assign(force:true)`); realm `BeatmapSetInfo` inserts / `Availability` turning LocallyAvailable → `retryPendingMaps` (joining mid-match after a download finishes works; clock rebuild runs even while frozen).
- Watching/scores (mirrors `SpectatorScreen`): `syncWatches` does differential Watch/StopWatch; `ensureUserMap` seeds from `room.Users` first and backfills missing users via `userLookupCache.GetUsersAsync` before retrying Playing users; `onUserStateChanged` only handles Add/Replace — Playing→`startGameplay`, Passed→`HasReceivedAllFrames=true` keeping the score for results, Failed→drop score and freeze the frame (no results), Quit→drop score + `stopWatching` + `cell.FadeGrey()` keeping a greyed last frame.
- `startGameplay(userId, state)` guard chain: missing ID/user; `WaitingForLoad/Playing && !CurrentMatchPlayingUserIds.Contains` **rejects mid-match joins**; no local beatmap; existing score+HasPlay skips; unknown ruleset / missing local beatmap. Builds `Score{ScoreInfo(beatmap,ruleset,user,state.Mods), Replay{HasReceivedAll=false}}`, snapshots `SpectatedItem ??= CurrentPlaylistItem.Clone()`, captures `clockGeneration` and only proceeds on the `Schedule`d double-check (same generation + cell still alive + same score reference): `syncManager.CreateManagedClock()` (exactly one managed clock per user) → `Seek(masterTime)` from the live position when `CurrentMasterTime>0` → `new TournamentPlayerArea → cell.AttachPlayArea → area.LoadScore(score)` (drives `TournamentSpectatorPlayer`, otherwise stuck on the loading spinner). Also snapshots `ScoreInfo.Mods` into `modsByUser` for provider weighting (+ `area.ScoreWeight`, see §5.3) and calls `RefreshWeights()`.
- Clocks: `setupClocks()` prefers reusing the global `beatmap.Value` (when it's the same object as the preview, the master takes over the playing track instead of starting a second one — mirrors `MultiSpectatorScreen`), else `QueryBeatmap + GetWorkingBeatmap`; **an empty-HitObjects placeholder beatmap returns false and retries on the next Assign** (`MasterGameplayClockContainer` ctor would throw); the old clock is `StopUsingBeatmapClock`+`Expire`d first; `generation++`; synchronous `LoadTrack()` when `!IsTrackUsable` (**tracks are deliberately never disposed**, see below); `MasterGameplayClockContainer + SpectatorSyncManager{ReadyToStart→performInitialSeek}`. `performInitialSeek` takes the min of each score's first frame, drops late joiners as outliers (±1000ms around the mean), `master.Reset(min,true)`, then `clocks.ProcessFrame()` to prime away the huge ElapsedFrameTime left by the teleport (otherwise a running clock eats the jump in one go, lands minutes early, and the ahead-rule freezes the whole field).
- Per-frame `Update: pumpPlayerClocks + checkAudioSource`. `pumpPlayerClocks`: **skip** when visible and `PlayerLoaded` (upstream `GameplayClockContainer` already pumps; pumping again double-advances); when hidden the session pumps instead and refreshes stale `WaitingOnFrames`. `checkAudioSource`:独 picks the `IsRunning && !CatchingUp && !WaitingOnFrames` clock closest to the master for exclusive audio and binds `area.ClockAdjustmentsFromMods` to the master; everything else is muted.
- `recreateScoreProvider`: reuse on `SetEquals`, else expire the old one and create a `WeightedTournamentLeaderboardProvider(users)` (a `MultiSpectatorLeaderboardProvider` subclass adding `TryGetCombo` and weight-adjusted `AdjustedTeamScores = round(score × weight(user))`) → `LoadComponentAsync` (generation+reference double-check) → on one-shot `OnFirstLoad` (NOT in the load callback: **the callback runs after dependency load but BEFORE `LoadComplete`**, which fires on the next update frame after `AddInternal`; binding there would bind raw and freeze, since `Assign` is frozen mid-match) flush AddClock + subscribe combo breaks (`Combo` hitting 0 with `Old>20` plays `breakSound` + `cell.NotifyComboBreak()`) → `updateScoreBindings`. The active rule is resolved from the room's current item (`RoundBeatmap.Matches` full-equality → map rule, else round default; every match start rebuilds so no mid-lobby refresh is needed); weights come from the session's Playing-time snapshot (`modsByUser`, same source as the cells — NOT the processor-side snapshot, whose one-time upstream build may be empty/stale), refreshed immediately when snapshots land. `updateScoreBindings`: sets `HasTeamScores=true` only when `TeamScores.Count==2 && TeamVersus`, and rebinds `ScoreDisplay.Team1/2Score` to the adjusted totals when a rule is active (raw otherwise) with **Unbind-then-BindTarget First/Last** (the provider instance changes on every rebuild; skipping the unbind throws); `awardMatchPoint()` therefore judges adjusted totals automatically (`TeamScore` stars are never multiplied — that would pollute bracket.json). Keep gameplay logs quiet: one verbose line per active rule, failures at `Debug` (`Important` pops notifications).
- `teardownVisuals`/`fullTeardown`/`Dispose`: `generation++` invalidates stale callbacks, clears plays/cells/dictionaries/scores/`SpectatedItem`/userMap/combo subscriptions/audio/`clockItemId`, `StopUsing`+`Expire`s the master, expires the provider, unbinds the ScoreDisplay, resets `HasTeamScores=false`; full adds `stopAllWatches + InRoom/Spectating→EnterIdle`. `Dispose` unsubscribes + stops all watches (same as `SpectatorScreen`).

### 5.3 Player / cell / score displays

- `TournamentSpectatorPlayer : MultiSpectatorPlayer` changes only two things: removes upstream's top-centre white username label (each `SpectateCell` has its own team-coloured label, and the label takes layout space so it must be disposed, not hidden); `CreateResults` picks between `SimpleResultsScreen` (`Tournament/UI/Results/Simple`), `V2ResultsScreen` (`Tournament/UI/Results/V2`), `LegacyResultsScreen` (`Tournament/UI/Results/Legacy`) and lazer's own `MultiSpectatorResultsScreen` according to `LadderInfo.ResultScreen` (`ResultScreenStyle`, configured in Setup), always `{AllowWatchingReplay=false, AllowRetry=false}` (re-watch/retry inside a cell would hijack the tournament UI stack). Clock/mod-adjustment/fail semantics are fully inherited. It additionally post-scales `ScoreProcessor.TotalScore` by `ScoreWeight` (from `TournamentPlayerArea.ScoreWeight`, computed once in `startGameplay` since mods lock at match start) with a reentrancy guard — one hook covers both the HUD counter (`GetBoundCopy`) and results (`ScoreInfo.TotalScore`); weight 1 subscribes nothing; accuracy/combo/rank untouched.
- `V2ResultsScreen` is a local port of the g0v0 V2 overview (MIT headers kept; type names preserved or `V2`-prefixed where g0v0 had replacements). It derives from `ResultsScreen` and keeps the inherited classic layout loaded but invisible (`Alpha=0`) so base lifecycle/update logic stays valid; its own `V2ResultsPanel` is added in `LoadComplete` and fills the screen; its left and right columns scale from the panel height so near-4:3 spectate cells use the full vertical space (horizontal overlap between the columns is intentional); the accuracy circle shrinks linearly between the 1110:610 and 750:610 aspect ratios while keeping its right-edge gap proportional to its size, then stays at 4/10 size and moves to the bottom-right area below that. The tournament variant is deliberately display-only: the g0v0 footer, score overview popover, details panel/statistics screen, favourite button and collection button are not ported, and the accuracy circle has no hover animation. `SelectedScore` is deliberately cleared in the constructor so the hidden classic statistics/score list do no duplicate work. V2-only strings live in `V2ResultsStrings`; do not modify `osu.Game` localisation. A headless visual smoke test lives in `Tests/UI/Results/V2/TestSceneV2ResultsScreen.cs`.
- `LegacyResultsScreen`/`LegacyResultsPanel` (`Tournament/UI/Results/Legacy`) is the osu!stable-style result screen ported from Torii via g0v0 (MIT/attribution headers preserved). It renders the stable ranking panel and health graph on a 768-high content design surface whose width adapts between the stable 1366-wide layout and a 4:3-friendly 1024-wide layout, while the dark backdrop, rotating rays and header strip stay full-bleed to the cell edges (the score content stays on its adaptive design surface and letterboxes at extreme aspect ratios); it hides the inherited classic layout and deliberately omits retry/watch-replay, favourites/collections and the below-fold online-ranking page so tournament cells stay display-only. `LegacyRankingPanel` uses the skin's legacy score font and classic ranking textures; `LegacyHealthGraph` replays `ScoreInfo.HitEvents` against the ruleset health processor off-thread. Mod icons use stable `selection-mod-*` textures, and legacy (`ScoreInfo.IsLegacyScore`) scores hide the synthetic Classic mod; lazer scores only keep the stable row when every mod resolves to a stable texture, otherwise the whole row switches to lazer's `ModDisplay`. Because osu-resources' classic skin no longer ships stable's mod icons, `Resources/Textures/Legacy` embeds the @2x icons as a final fallback. Smoke tests live in `Tests/UI/Results/Legacy/TestSceneLegacyResultsScreen.cs` and `TestSceneLegacyRankingPanelBundledModIcons.cs`.
- `TournamentPlayerArea` (line-by-line fork of upstream `PlayerArea`, only swapping the Player): **track-lifecycle anti-pattern fix** — `!TrackLoaded→LoadTrack()` but never held or disposed; `Dispose` is a no-op. Cells and the master share the same cached track instance, so disposing poisons every consumer (`TrackLoaded` stays true but points at a disposed object); lifetime belongs to the `WorkingBeatmap` cache + `MusicController`.
- `TournamentSpectatorPlayerLoader` (fork of `MultiSpectatorPlayerLoader`): neutralises `PlayerLoader`'s audio side effects, which are harmless on standalone screens but destructive when a cell loads **while the master clock is already playing that same shared track** (per-player reset → muffle + permanently silent music); ≤ two offender statements: entering adds a dim `volumeAdjustment` (reflected private field, detached immediately) plus cosmetic low/high-pass `AudioFilter`s on the global `TrackMixer` (removed before their cutoff transforms can attach; leaving them in is safe — their passthrough initial cutoffs never attach, later PlayerLoader cleanups act on disposed drawables); suspending stops the track — re-`Start()` right after when `IsRunning` was captured true (bass Stop = channel pause, so position is preserved and it is inaudible). Everything else (Mods/Ruleset lease, `pushWhenLoaded` gating, metadata display) mirrors official behaviour.
- `TournamentPlayerArea.LoadScore` chooses the loader at runtime: single-player reset (via `ResetPlayer`) passes `suppressAudioEffects=true` → uses `TournamentSpectatorPlayerLoader`; normal match start, full reset (`ResetSpectate`), and late joins use the official `MultiSpectatorPlayerLoader` to preserve the entrance blur/fade behaviour.
- `SpectateCell` (new): idle layer = background + centred OsuLogo + bottom-right team-coloured username; background priority mirrors `BackgroundScreenDefault` (`SeasonalBackgroundLoader` first, then the `MenuBackgroundSource` setting, `Beatmap→BeatmapBackground` without storyboard for perf, `Skin→TournamentSkinBackground` — upstream `SkinBackground` is internal so it's copied here, with `Equals` for dedup); the seasonal list only arrives after login, so early calls fall back to defaults; `LoadComponentAsync` + version counter guards stale loads, old background fades out over 400ms; `updateRelativeSizes` scales logo/username by height/256 (combo-break scale untouched); `NotifyComboBreak` mirrors the Argon miss feedback; `FadeGrey` keeps the quit grey last frame.
- `TournamentMatchScoreDisplay` is an empty `: MatchScoreDisplay` shell; binding is done by `updateScoreBindings` (adjusted totals when a rule is active, raw otherwise; upstream binds IPC Score1/2 in load). `TeamScore`/`TeamScoreDisplay`/`TeamDisplay`/`MatchHeader` match upstream behaviour (`MatchHeader` only switches explicit fields to the `field` keyword).

## 6. Room tab (Screens/Room/ — doesn't exist upstream)

`RoomScreen : TournamentScreen, IOnlinePlayLounge` replicates two upstream screens in one: `MultiplayerLoungeSubScreen` when not joined, `MultiplayerMatchSubScreen` once joined, staying in the room across screens.

- Dual `loungeContainer`/`joinedContainer + RoomCreateOverlay`, driven by `onlineState.RoomJoined` + `client.RoomUpdated` via `switchView` (fade swap + `rebuildJoinedRoom`/`clearJoinedRoom` + poller on/off + rejoin button). `Show`/`Hide` controls `LoungeListingPoller.TimeBetweenPolls` (visible and roomless: 120s idle / 15s otherwise, else 0 = stopped).
- The lounge listing does **not** use `RoomManager` — it uses `LoungeListingPoller + RoomListing + MultiplayerClient` directly (copied from the upstream lounge): 200ms-debounced search + status/permission dropdowns (bound to `OsuSetting.MultiplayerRoomFilter`) + showInProgress/showFull + ruleset, composed into `LoungeFilterCriteria(Category="realtime")`; `onListingReceived` does a differential update by RoomID.

## 9. Chat and referee commands (Components/ChatCommands/ + Online/Referee*)

Send chain (three send boxes — the RoomScreen joined view, `TournamentMatchChatDisplay{showTextBox}`, `SyncedControlPanelBottomBar` — all identical): resolve the target Channel per §8 → two-way draft bind → `Trim` on `OnCommit`, skip empties; leading `/` goes through `TournamentChatCommandHandler.HandleCommand` first, clearing and returning on true (handled or param error already reported); leading-`/` misses fall back to `PostCommand`, everything else to `PostMessage`. **Custom-command output always goes through `ChatNotifier.Notify` (`TournamentNotification{Transient/IsImportant}` when an `INotificationOverlay` exists, else an `ErrorMessage` injected into the channel) and never enters chat**; only fallback commands and the `timer`/`roll` `InfoMessage`s enter chat.

- `TournamentMatchChatDisplay : StandAloneChatDisplay`: `base(false)` disables the built-in box, adding its own only when `showTextBox` (sets `postingTextBox=true` via reflection); `CreateMessage` uses `MatchMessage` to tint usernames red/blue by `CurrentMatch.Team1/2.Players.OnlineID`.
- `TournamentChatTextBox`: Tab-completes `COMMANDS + COMMAND_ALIASES` when `/` has no space yet (case-insensitive; single hit completes plus a space, multiple hits cycle, Enter/Right confirms), falling back to username completion with a space (room `Username`s, `_`=space, `[a-zA-Z0-9-[]_]` tri-state); history shares one static `LimitedCapacityQueue<string>(100)` via reflection with Up/Down routed straight to `HistoryTextBox.OnKeyDown` for cross-box sharing.
- `CommandLineParser`: `'`/`"` equivalent quotes, quotes stripped, split on unquoted whitespace only, `""` kept as an empty arg; `--name value` / `--name=value` / `-x value` / `-xvalue` / `-x=value`, bare `--` makes the rest positional, long names case-insensitive. `mv` uses `s,t`; `settings` uses `n,p,t,q,m`.
- `TournamentChatCommandHandler.HandleCommand`: ① `UNSUPPORTED_COMMANDS=[join,chat,msg,query,watch]` swallowed with a notice (stops stock navigation from wrecking the tournament client); ② `Tokenize → ResolveCommandName(alias) → switch`, hit returns true (including param errors), `default:false` falls back to stock; empty command reports `Where's your command?`. Permissions: room-level hub commands share `ensureReferee` (in a room + `IsReferee` + hub Connected); `start`/`abort` use `IsHost||IsReferee` and call `MultiplayerClient` directly, bypassing the hub; `ping` only needs hub Connected, `timer` is purely local.
- User resolution: `tryResolveRoomUser` (`#id` or case-insensitive in-room username with `_`=space, must be in-room); `tryResolveUser` (in-room first, else async `GetUserRequest` backfill, may be out-of-room); `runForUsers` resolves everything first — one failure aborts the batch — then awaits each action, notifying + logging single failures without blocking the rest; hub exceptions always via `AsSingular().GetHubExceptionMessage()`. Slots display 1–16, stored +1 internally (2–17); teams `r/red/0` = red, `b/blue/1` = blue; types `head_to_head`/`team_versus`; queues `host_only`/`all_players`/`all_players_round_robin`; max `0`=unlimited else 2–16.

## 10. WebSocket data feed (tosu-compatible) (Online/TourneyDataWebSocketServer.cs)

An in-process **tosu-compatible ws v1 server** so existing tosu stream overlays keep working: `HttpListener` on `127.0.0.1:{PORT}` (`PORT = 50727`, tosu's own default 24050 stays free), `GET {PATH}` (**`/ws`**, 10 Hz v1 JSON broadcasts re-armed by `broadcastLoop`) and `GET {BACKGROUND_PATH}` (**`/backgroundImage`**, the current global beatmap's background parsed from the local `.osu` `[Events]` block, bytes cached per beatmap). The server is `[Cached]`+resident on `TournamentSceneManager` (see §3). JSON is serialised with `PropertyNamingPolicy = null` — **tosu's all-caps stat fields (`CS/AR/OD/HP/SR/BPM` and the numeric-string hit keys) must survive verbatim, never re-enable camelCase there**.

High-level structure (exact fields live in the code and `tourney-overlay-test/`, which agents may read directly):

- `buildPayload()` → `tourney.manager` (`ipcState` 0 playing / 1 idle from room state + live clocks, `bools.scoreVisible`, `chat` = last ~50 messages of the shared room `Channel` with team tints via `teamsByName`, `gameplay.score.left/right` = `getTeamScores()` from the leaderboard provider) + `tourney.ipcClients[]` (one per cell; **positional team split** over `RedCells.Concat(BlueCells)` — first half `left`, rest `right`; per player `user`/`spectating`/`gameplay` with score/accuracy/combo/hp/hits/tosu-style grade/UR/hitErrorArray/pp/per-player mods).
- `menu` → `state` (0 menu / 11 lobby per tosu's `GameState`), `gameMode`, `mods.str` (global mod acronyms) and `bm` = map card (`rankedStatus` via `toRankedStatus`, ms `time`, `stats` mirroring `SongBar`'s mod-adjusted values incl. async mod-adjusted SR + `originalStats` with the stored unmodded values).
- Data sources: `SpectateSession` (`ScoresByUser` / `RedCells` / `BlueCells` / `ClocksByUser` / `MasterClockTime`) plus per-cell `PlayArea.{UserId, ScoreProcessor, HealthProcessorPublic, GameplayStatePublic}` (processors + gameplay state captured on gameplay start, see §5.2/§5.3). `bm.time.current` prefers the spectator master clock while spectating (deliberately frozen through result screens, tosu parity) and falls back to the preview track.
- Live player data (`updateLiveData` → `updatePlayerLive`, class `PlayerLiveData`) is **change-driven, not round-robin**: every tick fingerprints each player's score/accuracy/combo/maxCombo/hit-event count and recomputes only moved players, so live PP keeps pace with the score. Timed difficulty attributes are cached per `map|ruleset|mods` (`timedKeyFor`), **prefetched for the room's current playlist item** (`prefetchTimedAttributes`, fired from `refreshStarRating` only while a room is joined so idle menu music changes don't cost anything) and computed off the already-parsed playable beatmap (`PlayableBeatmapWorkingBeatmap`, same trick as the in-game PP counter) — matches therefore start with PP live. `pp.fc` is computed once per play, `pp.maxThisPlay` only on miss-count changes, and UR/hit errors refresh independently of PP readiness. Scores/PP freeze at their last values through results and reset with the next play — intended tosu parity.
- UI: `SetupScreen.webSocketSection()` (switching a tosu ws v1 overlay's URL to `ws://127.0.0.1:{PORT}{PATH}` + a Copy URL row) and About-guide entries 8/9 link `SAMPLE_OVERLAY_URL` (the repo's `tourney-overlay-test` folder).

## 11. Notes for agents (gotchas)

1. **Respect the fork**: files under `Tournament/` not named above are mostly verbatim upstream forks (namespace + small adaptations only). Before editing, `diff ../osu/osu.Game.Tournament/<same path>` to confirm upstream behaviour; don't mix upstream-bug fixes and plugin logic in one commit.
2. **Game thread**: every callback touching rooms/UI/drawables (`RoomUpdated`/`UserStateChanged`/`LoadComponentAsync` callbacks, post-hub-await continuations) must `Schedule(...)` back to the main thread; hub/IO awaits use `ConfigureAwait(false)` + `FireAndForget`, but **never await non-hub work while holding an `OngoingOperationTracker` lease** (the RoomCreateOverlay lesson: it deadlocks busy and the room becomes un-leavable).
3. **Copy Room objects**: always `new Room{...}`-copy before `Join`/`Create`; never pass listing/external instances directly (`CopyFrom` overwriting the Playlist crashes). Call `SetPendingRoom` before `Create`/`Join`.
4. **Spectate invariant**: the broadcast local user must be `Spectating`; route any new `ChangeState` logic through `EnsureSpectateAsync`. Never call `rebuildLayout`/`Assign` while `IsFrozen` (WaitingForLoad/Playing) except on the forced reset path.
5. **Clocks/audio**: `SpectateSession`'s generation counter (`clockGeneration`) is the only defence against stale callbacks — capture + double-check in any new async attach; shared tracks are **never disposed** (see the `TournamentPlayerArea` comment); hidden subtrees don't run Update, so pump-requiring logic belongs in the session with a visible/hidden split (double-advance triggers the ahead-freeze). Cell-side loaders choose at runtime: single-player reset uses `TournamentSpectatorPlayerLoader` (neutralises track mute/stop + entrance filters); normal start, full reset, and late joins use upstream `MultiSpectatorPlayerLoader` to preserve the entrance blur/fade behaviour.
6. **Playlist semantics**: prefer Edit over Add when replacing the map (keeps the ID so the queue doesn't advance); Add only when the current item is Expired/missing; freestyle must clear allowedMods; don't simplify the `Matches` full-equality check down to BeatmapID-only.
7. **Chat**: custom-command output goes to notifications, never chat; `password`/`settings` display **never prints the password**; keep the two-step `close` confirm; `kick` goes through `MultiplayerClient`, don't switch it back to the hub; new commands must update `COMMANDS` (completion+help) and the alias reverse map.
8. **Bracket/storage**: bracket IO runs on a background thread + main-thread backfill, and `SaveChanges` is suppressed on load failure; `TournamentStorage` (`tournaments-lazer`) is isolated from upstream — watch `ChangeTargetStorage` when testing multi-tournament switches.
9. **UI constants**: `CONTROL_PANEL_WIDTH`, the 3-player pyramid layout (no Relative sizing), and the `REQUIRED_WIDTH=150+250+1366` height warning are hard stream-layout constraints — ask a human before resizing.
10. **Versioning/releases**: `LazerTourneyRuleset.Version` (currently `2026.1012.1`) is the update-check source — bump it on release; `SentryLoggerDisabler` swallows Sentry reports, so check local logs for crashes.
11. **Mod picker commit convention**: setting tweaks mutate the shared overlay `Mod` instances in place without changing the `SelectedMods` list, so `SelectedMods.BindValueChanged` alone misses them. Overlay-backed editors (`RoundBeatmapModEditor`, the About playground) commit/refresh on overlay `State → Hidden` instead of per-setting subscriptions — the editor sits behind the open overlay, so close-time handling loses no visible feedback. `RoundBeatmapModEditor` additionally skips no-op closes via `APIMod` value equality (avoids spurious stats recompute; the save prompt already compares serialised JSON).
